## Rencana

### Migrasi `20261008600000_pharmacy_cds_review`

- `pharmacy_cds_alerts` (append-only): hasil evaluasi CDS saat telaah per resep farmasi; `evaluation_id` per putaran,
  `medication_request_ids`, `level` mayor|sedang|info, `kind` (interaksi, dosis-ginjal, alergi, kontraindikasi,
  high-alert), `rule_code` + versi, judul/detail/rekomendasi, `prescriber_override` (override dokter di CPOE atas temuan
  blok, wajib ditinjau apoteker).
- `pharmacy_cds_alert_decisions` (append-only, satu per alert): konfirmasi | override (alasan ≥ 10) | usul.
- RLS FORCE + `tenant_isolation`, FK komposit dibungkus NO FORCE/FORCE, grant SELECT/INSERT, indeks manual di
  `MANUAL_INDEXES`. Tanpa SECURITY DEFINER.

### 4.5 · API `/api/v1/pharmacy` (modul `pharmacy-clinical`, izin `pharmacy.review.*`, lingkup unit = depo unit)

- `GET incoming`: kiriman CPOE ber-obat aktif yang belum diterima farmasi; depo dari kelas kunjungan (AMB → DEPO-RJ,
  IMP → DEPO-RI, EMER → DEPO-IGD) dalam lingkup.
- `POST prescriptions`: terima → nomor `R-YYMM-NNNN`, status `telaah` + riwayat, evaluasi CDS awal, event
  `pharmacy.service_started` (task 6 RJ BPJS lewat mesin task fase 2 bila tersedia).
- `GET prescriptions?status=`, `GET prescriptions/:id`: bentuk mengikuti kontrak demo (`pharmacyPrescriptionSchema`, id
  UUID) + stok depo per item dari ledger 4.6a (kolom stok).
- `POST :id/cds/evaluate`: `CdsService` fase 3 dengan konteks terkini (alergi, eGFR, BB, obat aktif), blok → mayor,
  peringatan → sedang; override dokter CPOE atas blok → alert mayor `prescriber_override`.
- `POST :id/alerts/:alertId/decision`, `POST :id/interventions` (notifikasi dokter penulis, resep tidak diubah),
  `POST :id/reviews` (setujui diblokir `CDS_UNRESOLVED`; tahan/sebagian beralasan; status telaah → penyiapan/ditahan).

### 4.6b · API `/api/v1/dispensing` (modul `dispensing`, izin `pharmacy.dispense.*`)

- `POST prescriptions/:id/prepare`: FEFO otomatis (`pickFefo`), batch lain wajib alasan; ledger `dispense` (pasien +
  kunjungan) satu transaksi; label barcode dosis per item; status → serah.
- `POST dispenses/:id/double-check` (apoteker kedua, sesi sendiri, `DOUBLE_CHECK_SAME_USER`), `POST dispenses/:id/handover`
  (high alert tanpa cek ganda → `HIGH_ALERT_DOUBLE_CHECK_REQUIRED`; event `pharmacy.dispensed`; `BillableRecorder` per item),
  `POST dispenses/:id/returns` (layak → `return`, tidak layak → `write_off`; event `pharmacy.returned`; biaya dikredit).
- `GET labels/:barcode` + eMAR: label farmasi menggantikan label lokal UUID order (tetap diterima untuk stok ruangan).

### Web

- Farmasi mode api: antrean (masuk/telaah/siap/serah), detail + kolom stok depo dari API stok, CDS + keputusan,

- E2E: telaah diblokir CDS → keputusan → setujui → siapkan FEFO → cek ganda apoteker kedua → serah → eMAR memindai label.
